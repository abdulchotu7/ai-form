# Persistent Live Model Cache per Provider

Fetched Models from `GET /models` were previously held only in the Settings panel's in-memory `live` state. The Model picker showed the union of curated and live Models, but on reload or when reopening Settings the live list was lost and the dropdown fell back to curated only until the user clicked **Fetch available Models** again.

We persist the live list as a new top-level `chrome.storage.local` key `liveModels: Record<ProviderId, string[]>` — separate from `settings`, so no settings-schema migration is required. Each Provider's live list is stored under its `providerId` (including `custom` as a single slot for the current Custom Provider endpoint; endpoint-specific sharding is deferred). The cache lives **forever until the next successful Fetch** — no TTL, no background expiry, no auto-fetch on load. The Settings panel loads the cache on mount and shows `merged = curated ∪ live` (deduped, sorted). The **Fetch available Models** button is the sole writer: on success it overwrites `liveModels[providerId]` and shows the merged result; on failure it clears `liveModels[providerId]` so the picker falls back to curated and shows a non-blocking error `Could not fetch models — curated models still available.` If the currently selected Model is not in the new `merged` set (retired), the selection resets to the Provider's default curated Model rather than lingering as a stale `(current)` entry.
